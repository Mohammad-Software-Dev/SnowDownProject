# Snowdown — Inputs Needed From the User

The project can begin before every item below is resolved. Unanswered items remain TBD or use reversible prototype defaults.

## Needed before serious visual production
1. **Visual references** — 5–15 images showing the desired character style, environment, lighting, UI mood, snow look and overall level of stylization. Put them in `references/`.
2. **Character direction** — choose/provide a rough reference for player body proportions, clothing silhouette and how much of the body should be visible in first person.
3. **Map mood reference** — choose a target such as alpine village, school snow day, mountain resort, suburban park, fantasy winter town, etc., plus 2–5 reference images.

## Needed before platform/production lock
4. **Platform priority** — confirm Windows-first and whether macOS/Linux should be supported during early testing or only later.
5. **Engine lock** — current recommendation is to keep Godot 4/GDScript provisional until the first networked prototype proves the workflow. Confirm if you already require Godot.
6. **Player-count target** — preferred initial public target (for example 8, 12 or 16 players) so network/map testing has a concrete budget.

## Needed before online production services
7. **Hosting/business constraints** — expected budget tolerance for dedicated servers/backend.
8. **Account/social scope** — Steam-only identity at first, custom account system, or another platform strategy.
9. **Chat/moderation scope** — whether launch needs text chat, voice chat, both, or neither.

## Useful but not blocking
10. Audio references/music direction.
11. UI references.
12. Logo/title treatment if one exists.
13. Accessibility priorities beyond the baseline spec.
14. Monetization preference, only when core gameplay is validated.

## Do not block prototype on
Final movement numbers, projectile gravity/drag, catch timing, head/body scoring values, snow deformation amount, ranked rules, progression economy, or monetization. Keep these configurable and validate through playtests.
